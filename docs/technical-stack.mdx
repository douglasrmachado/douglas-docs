# Technical Stack

I work with a mix of development languages/frameworks and documentation-specific tools. The developer background feeds directly into how I write and build docs.

## By category

| Category | Tools |
| --- | --- |
| Languages | TypeScript, JavaScript |
| Frameworks | React, React Native, Node.js |
| Documentation platforms | Docusaurus, Mintlify, ReadMe |
| Docs as Code / collaboration | Git, GitHub |

## Why both sides matter

Knowing TypeScript, React, and React Native means I can read a mobile app's source directly instead of relying only on what a developer tells me. Knowing Node.js means I've written the backend an API like this actually runs on. Together, that makes it easier to spot when a doc is wrong, not just when it's incomplete.

On the documentation side, Docusaurus, Mintlify, and ReadMe cover the three most common ways teams publish developer docs today: a fully custom static site (Docusaurus), a hosted docs-as-code platform (Mintlify), and an API-first documentation product (ReadMe).
