# Experience

I'm currently working as a Technical Writer, with a background in software development.

That mix means I move comfortably between two worlds: I can read and reason about code, APIs, and system behavior, and I can turn that understanding into documentation that a developer, or a less technical stakeholder, can actually use.

## What that looks like in practice

- Writing and maintaining documentation for **APIs and SDKs**, including reference material, guides, and examples.
- Working with **SaaS products**, where documentation has to keep pace with fast-shipping engineering teams.
- Collaborating with developers directly through **Git and GitHub workflows** (branches, pull requests, and reviews), rather than a separate, disconnected content process.
- Applying a **Docs as Code** approach: docs live in version control, go through review, and are checked and deployed like software. More on that in [Docs as Code](/docs/docs-as-code).
